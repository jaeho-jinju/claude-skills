# Explain Like

기술적인 내용을 지정한 나이도 따라올 수 있게 다시 설명합니다.
뜻은 그대로 두고, 어려운 표현만 쉬운 말로 바꿉니다.

## 나이 인자 파싱

인자의 **첫 번째 토큰**이 나이를 나타내면 그 값을 대상 나이로 사용합니다. 나머지 토큰을 설명 대상으로 간주합니다.

나이로 인식하는 패턴 (대소문자 무관):
- 숫자만: `8`, `10`, `12`
- 숫자 + 살: `8살`, `10살`, `12살`
- 숫자 + 세: `8세`, `10세`, `12세`
- ELI 패턴: `ELI5`, `ELI10`, `ELI12`

나이 인자가 없으면 **기본값 12살**을 사용합니다.

### 예시 파싱

| 입력 | 대상 나이 | 설명 대상 |
|------|-----------|-----------|
| `8살 src/api.ts` | 8살 | src/api.ts |
| `10 이 에러가 뭔지` | 10살 | 이 에러가 뭔지 |
| `ELI5 src/reducer.ts` | 5살 | src/reducer.ts |
| `src/api.ts` | 12살(기본) | src/api.ts |
| (없음) | 12살(기본) | 최근 대화 맥락 |

## 핵심 원칙

- 원래 뜻을 바꾸지 않습니다.
- 짧은 문장과 쉬운 단어를 우선 사용합니다.
- 세부사항보다 먼저 큰 그림을 설명합니다.
- 어려운 용어를 꼭 써야 하면 한 문장으로 바로 풉니다.
- 비유는 맞을 때만 사용합니다.
- 불확실함이나 한계도 쉬운 말로 유지합니다.
- 사용자의 언어를 따릅니다.

## 설명 대상 결정

### 인자가 있는 경우

- 인자가 **파일**이면: 파일 내용을 읽고 설명합니다.
- 인자가 **디렉토리**이면:
  - 관련 소스 파일과 문서 파일 목록을 찾습니다.
  - 파일이 5개 이하이면 함께 읽고 한 번에 설명합니다.
  - 파일이 6개 이상이면 어떤 파일을 설명할지 먼저 물어봅니다.
- 인자가 일반 문장이나 질문이면: 그 문장과 현재 대화 문맥을 기준으로 설명합니다.

### 인자가 없는 경우

- 현재 대화에서 가장 최근에 나온 코드, 문서, 로그, 에러, 테스트 결과를 기준으로 설명합니다.
- 설명 대상이 불분명하면 무엇을 쉽게 설명할지 한 문장으로 다시 물어봅니다.

## 설명 순서

1. 먼저 핵심 질문을 잡습니다.
   - 이것이 무엇인지
   - 왜 있는지
   - 무엇이 문제인지
   - 왜 실패했는지

2. 중요한 부분만 고릅니다.
   - 사용자가 깊이를 원하지 않으면 구현 세부는 줄입니다.

3. 어려운 말을 쉬운 말로 바꿉니다.
   - API: 프로그램끼리 부탁을 주고받게 해주는 창구
   - Database: 정보를 정리해 둔 큰 공책
   - Cache: 자주 쓰는 것을 가까이에 둔 작은 서랍
   - Refactor: 기능은 그대로 두고 더 깔끔하게 다시 정리하는 것

4. 아래 순서로 설명을 다시 만듭니다.
   - 한 줄 요약
   - 쉬운 단계 설명
   - 필요할 때만 비유
   - 왜 중요한지

5. 마지막으로 다시 읽습니다.
   - 대상 나이의 아이가 "그 말이 무슨 뜻이야?"라고 물을 단어가 남아 있으면 더 쉽게 고칩니다.

## 코드 설명 규칙

- 코드가 무엇을 하려는지부터 설명합니다.
- 문법보다 입력, 처리, 결과를 먼저 설명합니다.
- 줄마다 기계적으로 읽지 말고 같은 역할끼리 묶습니다.
- 버그라면 기대한 동작, 실제 동작, 어긋난 이유를 쉽게 설명합니다.
- 더 깊은 설명이 필요하면 큰 개념 -> 구체 예시 -> 필요한 코드 순서로 내려갑니다.

## 문서와 로그 설명 규칙

- 각 섹션이 하는 일을 한 문장으로 줄입니다.
- 결정, 위험, 다음 행동을 쉬운 말로 뽑아냅니다.
- 절차 설명은 사람과 행동 중심 문장으로 바꿉니다.
- 필요 없는 제목 반복은 줄입니다.

## 출력 형식

가능하면 아래 형식을 사용합니다.

### 한 줄로 말하면
가장 중요한 뜻을 한 문장으로 설명합니다.

### 쉽게 설명하면
2개에서 5개 정도의 짧은 단계로 설명합니다.

### 비유하면
정말 도움이 될 때만 씁니다.

### 그래서 중요한 점
왜 신경 써야 하는지 짧게 설명합니다.

## 하지 말아야 할 것

- 사용자를 깔보는 말투를 쓰지 않습니다.
- 비유를 맞추려고 없는 사실을 만들지 않습니다.
- 설명 없는 약어를 남기지 않습니다.
- 요청하지 않은 예외사항을 한꺼번에 너무 많이 늘어놓지 않습니다.
- 강의처럼 길게 끌지 않습니다.
