# Prompt Refine

사용자가 작성한 프롬프트를 더 명확하고 실행 가능한 형태로 다듬습니다.
`/my-prompt-refine`, `/my-prompt-refine 프롬프트 내용`처럼 사용할 수 있습니다.

## 입력 결정

1. 인자가 있으면 그 텍스트를 개선할 프롬프트로 사용합니다.
2. 인자가 없으면 대화 맥락에서 가장 최근에 언급된 프롬프트를 사용합니다.
3. 무엇을 개선해야 하는지 불분명하면 한 문장으로 확인 질문을 합니다.

## 분석 방법

아래 항목 중 개선이 필요한 부분을 자동으로 판단합니다. 분석 내용은 출력하지 않습니다.

- **명확성**: 모호하거나 중의적인 표현을 구체적인 지시어로 교체
- **구체성**: 막연한 요청에 범위, 조건, 제한을 추가
- **맥락**: 필요한 배경 정보나 전제가 빠져 있으면 추가
- **출력 형식**: 원하는 결과물의 형태(길이, 구조, 언어 등)가 없으면 명시
- **역할 설정**: Claude에게 역할을 부여하면 더 나은 답변이 나오는 경우 추가
- **제약 조건**: 하지 말아야 할 것, 스타일 요구사항 등이 필요하면 추가
- **Claude 특화**: Claude의 추론 능력을 잘 활용하는 방향으로 구조를 개선

불필요한 항목은 건드리지 않습니다. 원래 프롬프트가 이미 충분한 부분은 그대로 둡니다.

## 출력 규칙

- **개선된 프롬프트 텍스트만** 출력합니다.
- 리뷰 코멘트, 변경 이유, 항목 설명, 헤더 일체를 출력하지 않습니다.
- 코드 블록(```) 없이 순수 텍스트로 출력합니다.
- 원래 프롬프트의 의도와 언어(한국어/영어)를 그대로 유지합니다.
- 과도한 확장은 하지 않습니다. 핵심 의도를 명확하게 하는 데 집중합니다.

## 승인 및 전송

개선된 프롬프트를 출력한 후, AskUserQuestion 도구를 사용하여 선택지를 제시합니다:

- question: "어떻게 할까요?"
- header: "다음 단계"
- options:
  - label: "전송", description: "이 프롬프트로 바로 실행합니다"
  - label: "수정", description: "수정할 내용을 입력해주세요"
  - label: "취소", description: "그냥 종료합니다"

응답 처리:
- **전송**: 개선된 프롬프트를 새 요청으로 즉시 처리합니다.
- **수정**: 사용자의 수정 요청을 받아 프롬프트를 다시 개선하고 AskUserQuestion을 다시 호출합니다.
- **취소**: 그대로 종료합니다.
